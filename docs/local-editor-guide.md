# 本地中文编辑与英文同步

后台仅本机运行，不与线上自动同步。网站版式、图片、地图、完整页尾和业务信息保留。

## 自己打开

在 PowerShell 中运行：

```powershell
Set-Location 'E:/Ellis-Services/Perth Pipe Power/source'
npm run editor:dev
```

打开终端输出的实际地址。默认尝试 `http://127.0.0.1:4200/__editor/`；端口占用时自动尝试后续端口，不关闭其他进程。保持该终端运行，按 Ctrl+C 停止服务。关闭浏览器不会删除已保存草稿。

## 日常编辑

1. 筛选并选择页面。默认显示已上线中文；有本地草稿时显示草稿。
2. 点选预览中的正文，或使用“文字位置”选择正文、FAQ、按钮文字、图片说明及 SEO。
3. 修改中文，点击“保存中文草稿”。只有本地服务确认成功才会显示保存成功。
4. 在此聊天通知助手，例如：“about.html 中文修订4已保存，请同步英文，暂不部署。”
5. 助手仅同步该修订的变更。后台“中英文变更与确认”展示中英文修改前后，可切到只读英文预览。
6. 核对后可标记“确认英文与中文候选”。这只是本地记录，不部署；需要上线时在聊天另行明确授权。

再次修改并保存中文后，旧英文提案和旧确认立即失效。两个窗口同时编辑时，过期保存返回冲突，不强行覆盖。当前输入保留，可复制后重新载入人工合并。

“已保存历史”保留本页最近20次修订。恢复会生成新修订，不改动其他页，英文需重新同步。

## 旧草稿和编辑边界

旧版草稿保留。首次迁移保存会完整备份到 `.local-editor/drafts/legacy/`，不自动删除。共用导航标签的旧改法显示在页面下方备查，不直接套到现有导航。

页面或已审译文基线变化时拒绝应用失效草稿，需助手核对。请不要手动删除草稿解决错误。

本次开放文字、FAQ、按钮标签和 SEO；共享导航／页尾、联系方式、价格等事实仍锁定。图片上传、更换图片、修改内链目标及正式候选应用仍是后续事项，由助手按明确指令处理；不支持自由拖拽或新增模块。

## 助手使用的本地工作流

```powershell
npm run editor:changes -- about.html
node .build/tools/editor/cli.mjs proposal about.html <本地英文提案JSON文件>
```

提案必须绑定导出中的中文修订号和 chineseHash，必须覆盖全部且仅本次改动。CLI不调用在线翻译、Git、Vercel或邮件服务。后台保存、历史和提案在 Git 忽略的 `.local-editor/`；生产构建不读取这些文件。
